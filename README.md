# «Всё для дверей»: интернет-магазин дверной фурнитуры (тестовая версия)

Тестовая версия интернет-магазина дверной фурнитуры на 22 бренда (Colombo Design, Krona Koblenz, AGB, Tupai, Venezia, Fratelli Cattini, Morelli, FUARO, Armadillo, PUNTO и др.). Домен магазина: вседлядверей.рф. Данные компании лежат в `src/lib/company.ts`. Цены ориентировочные до загрузки прайса поставщиков. Сборка `LAUNCH_ONLY=1 npm run build` оставляет в каталоге только стартовые бренды (Colombo Design, TUPAI).

Структура сайта (разделы, URL, теги, бренды, перелинковка, sitemap) построена по SEO-проектированию: семантика Wordstat, SERP-кластеризация Яндекса, анализ конкурентов.

## Стек

- [Astro 5](https://astro.build), статическая генерация (SSG), без клиентского фреймворка.
- Данные — JSON в `src/data/` (товары, тексты, реестр страниц).
- Деплой — GitHub Actions → GitHub Pages (`.github/workflows/deploy.yml`).

## Запуск

```bash
npm ci
npm run dev        # http://localhost:4321/vsedlyadverey/
npm run build      # сборка в dist/
```

## Где что лежит

| Путь | Что это |
|---|---|
| `src/data/registry.json` | реестр всех страниц: URL, H1, тип, приоритет (из SEO-проектирования) |
| `src/cms/products/*.json` | товары, один файл на модель: варианты покрытий, цены, характеристики, фото, тексты карточки |
| `src/cms/sections/*.json` | разделы каталога любой вложенности (родитель, адрес, меню, SEO, тексты); создаются в админке, адрес = цепочка родителей + slug |
| `src/cms/blog-hubs/*.json` | рубрики блога |
| `src/cms/pages/*.json` | тексты остальных страниц реестра: главная, /catalog/, типы дверей, бренды-хаб |
| `src/cms/brands/`, `src/cms/series/` | страницы брендов и серий |
| `src/cms/articles/*.json` | статьи раздела «Инструкции и советы» |
| `src/cms/service/*.json` | доставка, оплата, гарантия, шоурум, FAQ (и отключённые B2B-страницы) |
| `src/cms/reviews.json`, `src/cms/settings/*.json` | отзывы; компания и контакты, служебные тексты, главная, меню каталога и бренды |
| `public/admin/` | админка Sveltia CMS; `config.yml` генерируется `scripts/gen-cms-config.mjs` при сборке |
| `src/lib/data.ts` | слой данных: выборки товаров для категорий, тегов, брендов, правила индексации |
| `src/pages/` | маршруты: `catalog/[...path]`, `brands/[...path]`, `product/[slug]`, `blog/[slug]`, `[slug]` (типы дверей и служебные) |
| `public/images/products/` | фото товаров (с сайтов брендов и дилеров, для демо) |

## SEO, заложенное в шаблоны

- Канонические URL со слэшем, `index/noindex` по порогу товаров на теговых и бренд-страницах.
- JSON-LD: Organization, WebSite+SearchAction, BreadcrumbList, CollectionPage+ItemList, Product+Offer/AggregateOffer, Article, FAQPage, Brand.
- `sitemap.xml` и `robots.txt` генерируются при сборке.
- Внутренняя перелинковка: плитки подразделов, подборки-теги, «по брендам», «смотрите также», «инструкции по теме», «с этим покупают».

## Переезд на домен

В `astro.config.mjs` (или через переменные окружения при сборке): `SITE_URL=https://домен.ru BASE_PATH=/ npm run build`.

## Ограничения демо

- Цены ориентировочные, из открытых источников; наличие условное.
- Корзина работает в браузере (localStorage), заказы и формы никуда не отправляются.
- Фото товаров взяты с сайтов брендов и дилеров для демонстрации; для рабочего запуска нужны фото от поставщика или разрешение правообладателей.

## Админка

`/admin/` (Sveltia CMS, git-based): правки сохраняются коммитами в этот репозиторий с пометкой `[skip ci]`,
кнопка «Publish Changes» шлёт `repository_dispatch: sveltia-cms-publish`, на который деплой-workflow пересобирает сайт.
Вход: GitHub-аккаунт с правами на репозиторий (кнопка «Войти с помощью токена доступа») или OAuth через
`backend.base_url`, когда будет развёрнут [sveltia-cms-auth](https://github.com/sveltia/sveltia-cms-auth).
Новые записи админки могут называться кириллицей: адреса строятся транслитерацией (`translit` в `src/lib/data.ts`), поле «Адрес страницы (URL)» его переопределяет.
Кнопка «View on Live Site» ведёт на `/go/<коллекция>/<файл>/` (`src/pages/go/`), страница переадресует на итоговый URL.
Реестр проектирования (`src/data/registry.json`) по-прежнему задаёт бренды×категории, серии, типы дверей и служебные страницы; разделы каталога и рубрики блога из него больше не берутся.
Инструкция для редакторов: `Инструкция по управлению сайтом.pdf` в папке проекта.

## Адреса и переадресации

- Сайт: https://takedown-desing.github.io/vsedlyadverey/, админка: `/admin/`. Старое имя репозитория `maniglia-shop` занято
  репозиторием-переадресатором (https://github.com/takedown-desing/maniglia-shop): каждая старая страница ведёт на тот же путь здесь.
- Смена адреса записи в админке не даёт 404: после сборки `scripts/save-cms-state.mjs` сохраняет карту адресов
  (`src/cms/settings/url-map.json`) и накопленные переадресации (`redirects-auto.json`), workflow коммитит их с `[skip ci]`.
  Следующая сборка сравнивает адреса и генерирует страницы переадресации (`src/pages/[...old].astro`), цепочки схлопываются.
  Удалённые или скрытые записи ведут на родителя. Ручные переадресации: `src/cms/settings/redirects.json` (админка).
- Не пишите `[skip ci]` в сообщениях обычных коммитов: GitHub пропустит деплой.

## Excel и CSV: выгрузка и загрузка каталога

`scripts/catalog-csv.mjs`: `export <папка>` пишет `products.csv/.xlsx` (строка = вариант покрытия, колонки «Х: …» = характеристики, SEO-поля) и
`sections.csv/.xlsx`; `import <файл.xlsx|.csv> [products|sections] [--dry]` применяет файл к `src/cms`; `import-pending` берёт файл, загруженный
в админке (`src/cms/settings/import.json`, файлы лежат в `import/`), пишет отчёт в `import-report.json` и переносит файл в `import/done/`.
Выгрузка собирается после каждой сборки в `dist/admin/export/`, страница со ссылками и правилами: `/admin/csv/` (кнопка «Excel / CSV» в админке).

- Для нового товара обязательно только «Название» (синонимы колонок: «Наименование», «Стоимость», «Цвет», «Производитель»… см. `ALIASES`).
  Без вариантов создаётся покрытие «стандарт», без фото карточка показывает `/images/no-photo.svg`, без цены «Цена по запросу».
- Шапка ищется в первых 15 строках (строки-заголовки прайса пропускаются), номера строк в отчёте совпадают с Excel. `.xls` не принимается.
- Строка без ID с названием существующего товара обновляет его; фото по той же ссылке не перекачивается; при удалении товара его фото
  удаляются, если не используются другими. Группа цвета без колонки определяется по названию покрытия.
- Адрес нового товара всегда из названия (`nameSlug`: транслит как в `src/lib/data.ts`, до 80 символов, занятый получает `-2`); при явном ID
  пишется в `slug`. Отчёт (`import-report.json`) хранит `links` (новые/изменённые/удалённые с адресами) и `summary`; страница `/admin/csv/`
  показывает их ссылками, пустой новый раздел помечается вместо ссылки.
- Пустая ячейка = не менять, `-` = очистить, «Удалить» = `товар`/`вариант`. Повторная загрузка выгрузки ничего не меняет (проверено на CSV и XLSX).
- В CI после импорта фото приводятся к 800×800 (`scripts/normalize-images.py`, готовые файлы пропускаются). Результат импорта коммитится
  обратно с `git pull --rebase --autostash`; если сохранить не удалось, сборка падает, а файл остаётся в очереди до следующей публикации.
