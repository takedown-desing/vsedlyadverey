# Блочный формат контента (разделы каталога и товары)

> С 07.10.2026 контент лежит в `src/cms/` по одному файлу на сущность и правится через админку `/admin/`. Отличия формата: `specs` хранится списком `{k, v}`, таблицы блоков строками `ячейка | ячейка`, тексты карточки (`intro`, `blocks`, `faq`) внутри файла товара. Описание ниже про смысл полей остаётся в силе.

Контент хранится как массив блоков `blocks`. Движок рендерит каждый тип своим компонентом: карточки, таблицы, шаги,
SVG-инфографика. Markdown допускается только внутри полей `md` / `text` (жирный, ссылки `[анкор](/catalog/.../)`, списки).
Длинное тире «—» запрещено везде (дефис, двоеточие, запятая). Факты только проверяемые, общеотраслевые или из данных
товара/бренда. Никаких выдуманных цен, рейтингов, отзывов, лет на рынке, статистики продаж.

## Типы блоков

| type | поля | как выглядит |
|---|---|---|
| `text` | `title`, `md` (300–900 знаков) | заголовок H2 + абзацы |
| `cards` | `title`, `items:[{title, text, icon?}]` 3–6 шт. | сетка карточек-преимуществ; `icon` из списка: handle, rosette, lock, padlock, cylinder, hinge, closer, slide, stop, bolt, eye, seal, glass, window, furniture, kit, truck, shield, store, check, box |
| `table` | `title`, `head:[…]`, `rows:[[…]]`, `note?` | таблица сравнения/подбора (3–8 строк, 2–5 колонок) |
| `steps` | `title`, `items:[{title, text}]` 3–6 шт. | нумерованные шаги (как выбрать, как установить) |
| `checklist` | `title`, `items:[…]` 4–8 шт. | список с галочками (что проверить перед покупкой) |
| `callout` | `kind: tip\|warn`, `title`, `text` | выделенная плашка-совет или предупреждение |
| `bars` | `title`, `unit`, `items:[{label, value}]` 3–7 шт., `note?` | SVG-инфографика: горизонтальные столбцы (например, нагрузка на петли разных типов, кг) |
| `range` | `title`, `unit`, `items:[{label, from, to}]` 3–6 шт., `note?` | SVG-инфографика: диапазоны (толщина двери под модель, вес полотна по классам доводчиков EN 1154) |
| `stats` | `items:[{value, label}]` 3–4 шт. | крупные цифры-факты (например «8 мм · стандартный квадрат ручки») |

`value`, `from`, `to` — числа. Цифры только реальные: стандарты (EN 1906, EN 1154, EN 1125, ГОСТ 5089), типовые
размеры (квадрат 8 мм, backset 50 мм, межосевое 85/96 мм, цилиндры 30/30…), паспортные данные моделей из каталога.

## Раздел каталога (`src/data/content/sections/*.json`)

```json
{
  "url": "/catalog/dvernye-petli/skrytye/",
  "title": "...", "description": "...", "h1": "...", "lead": "1–2 предложения",
  "blocks": [ ... 6–9 блоков, суммарно 3000–5500 знаков для category/subcategory/home/door-type/kit, 1800–3000 для tag ... ],
  "faq": [ {"q": "...?", "a": "2–4 предложения"} ]  // строго 6–8 вопросов
}
```
Структура раздела (адаптировать под тему):
1. `text` «Что такое / чем отличаются» (сущность + ключевые атрибуты)
2. `cards` «Виды / типы» или «Преимущества»
3. `table` «Как подобрать: сравнение/подбор по параметрам»
4. `bars` или `range` (инфографика по реальным параметрам)
5. `steps` «Как выбрать» или «Как установить»
6. `checklist` «Что проверить перед покупкой»
7. `callout` совет
8. `text` «Бренды в каталоге» со ссылками на бренды/подразделы из реестра
Внутренние ссылки: 4–8 ссылок на URL из `research/structure/pages-registry.csv` (только существующие URL).

## Товар (`src/data/content/products/*.json`)

```json
{
  "slug": "…",
  "intro": "2–3 предложения, 250–450 знаков: что это и для чего",
  "blocks": [
    {"type": "cards", "title": "Особенности модели", "items": [ 3–4 карточки по фактам из specs/описания ]},
    {"type": "table", "title": "Для каких дверей подходит", "head": ["Параметр", "Значение"], "rows": [...]},
    {"type": "checklist", "title": "Что учесть при покупке", "items": [ 3–5 пунктов: что докупить, совместимость, размеры ]},
    {"type": "text", "title": "Уход и эксплуатация", "md": "..."}   // опционально
  ],
  "faq": [ 3–4 вопроса по этой модели ]
}
```
Суммарно 1200–2200 знаков на товар. Только факты из JSON товара (specs, description, material, variants) и
общеотраслевые знания о типе изделия. Не выдумывать паспортные цифры, которых нет в specs.
